# My Week working wireframe

This is the first P01-P06 working review, not approval or production integration. It replaces the old agenda outline only in the expanded preview. Approved Today/Homeguard core, archived screens, production routes and backend remain unchanged.

## Design and references

A calendar-led personal dashboard uses HALO's existing Instrument Sans, Fraunces, Onest and blue/teal shell. One connected calendar, a flat agenda and saved-for-later shelf replace many scorecards. A small botanical line sketch is decorative, not an environmental measurement. Week/month/agenda controls and task scheduling take functional inspiration from [Todoist's calendar documentation](https://www.todoist.com/help/todoist/features/use-the-calendar-layout-in-todoist-lPHRQTu0o) and [TickTick](https://ticktick.com/). [Mazah's official Challenge profile](https://www.congressionalappchallenge.us/25-NC08/) supports the household-to-community product connection; its calendar layout was not independently inspected or copied. References are inspiration, not evidence that a particular visual treatment wins competitions.

## Implemented in this review

- Monday-based week/month calendar, today/period navigation, selected day, globally chronological agenda, category/search, completed-item inclusion, waiting/earlier items, archived task access and unscheduled saves. Search includes matching completed and dated tasks outside the selected period.
- Same canonical shared action IDs as Homeguard/Explore/Luna. Title/date/status edits use captured revisions; failures retain reviews. Add, complete/reopen, waiting, pause, archive/restore, explicit task-only delete, focus selection, private preparation and edit history are visit-local. Existing origin records never automatically generate commitments. Known home/project links reopen the exact source record; other origins retain their workspace entrance.
- All-day dates stay calendar dates. Optional timed tasks use a chosen IANA timezone and bounded duration; ambiguous/nonexistent DST wall times are rejected. Supported timezone choices are currently a small US/UTC list, not a worldwide resolver.
- Real RFC5545 ICS download of saved title/schedule only, with escaped/folded text, exclusive all-day end and UTC timed instants. No notes/evidence exported implicitly, calendar sync, provider call or reminder delivery. A downloaded file cannot be revoked.
- Weekly fixed-calendar versus seven-days-after-completion recurrence configuration. A completed recurring action can deliberately prepare one next occurrence with a stable deduplication key. No automatic scheduler, series-wide edit, timed recurrence or delivered reminder is claimed.
- Optional action streak, off by default, based only on known completion dates. No rewards for symptom logging, inferred environmental benefit or punitive reset copy. Older completions without timestamps do not earn invented streak days.
- Journal: empty first use/log today/remembered date selection, 90-day window, at most62 recalled dates, group selection, seven symptom choices, explicit Felt fine, no default severity, possible illness, private note, save/edit/recent seven, confirmed delete/undo. Recalled batch keeps existing entries and retains failed dates for retry. Journal context never silently enters Luna.
- Patterns: twelve-week84-day grid, logged/fine/unlogged distinction, group/factor controls, day detail/edit and selected-group export without private notes. No environmental observations are fabricated. With the current disconnected history adapter the comparable count is0 and trends/findings remain unavailable, not invented or clinically interpreted.
- Season: season/year selection, household check-in coverage, scheduled-date completed-task count with its limitation, dismissible next-step prompt and real JSON overview export. Full measured trends/test/participation joins remain integration work.
- Outdoor preparation: retained activity/coarse-place/date/duration/preferred-period draft, separate per-factor missing coverage, official source links and one canonical saved task. Watches are explicit preferences only. No GPS, invented future hourly forecast, safety rating or automatic rescheduling.
- Load a sample week is an explicit review control, not production initialization. Everything private remains in memory and reload resets it. Review loading/error/offline/save-error/conflict controls and failure guards do not prove live durability.

## Backend and remaining review gates

The current production route registry still excludes /plan and expanded record routes. Existing /api/journal, /api/history and Journal findings/summary routes supply part of the foundation; they are not wired to these new components. Revised logged/fine/recalled/illness/source-basis analysis remains required. Current backend has no new durable action/occurrence/forecast/commitment/generation/tool contracts. Backend ownership stays with Vibhav and the handoff is deferred.

Required contracts: owner-scoped shared actions and atomic action+metadata edits, complete immutable origin/evidence references, full lifecycle permissions and revision/idempotency/status reconciliation; all-day versus timed event schemas and exhaustive timezone/DST tests; recurrence/occurrence cancellation and source-change notices; durable delivery jobs with explicit channel preferences; forecast horizons/source timestamps/coverage and outdoor-plan watches; authoritative Journal first-use and logging semantics, versioned descriptive analysis and same-home compatible histories; season-owned-record joins; selected/private exports, recovery, consent and retention.

Paused/archived records must have reviewed server reminder and project-progress semantics. Export/delete/recovery must cover all new records and jobs. Full-series recurrence edits, notification delivery, live forecast comparison, environmental charts/findings, public opportunity cancellation propagation, optional recovery, Spanish, physical Safari and screen-reader end-to-end checks are not verified here. Do not claim those flows live or freeze this design before Yogi's explicit approval.
